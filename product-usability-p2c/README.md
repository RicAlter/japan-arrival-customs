# P2-C 业务适用性只读候选

基于P2-B `dfc4537`。此目录只做只读分析和独立候选验证，不接入运营入口、不修改Skill/计算引擎、不打开或写入SQLite、不调用网站、D1、正式输出或WorkBuddy。

## 三种事项

- **影响当前报单**：本批必要字段缺值、现有值未确认/缺来源、本批两个确认来源冲突。保留具体需处理字段，不以历史候选自动补值。这里的当前业务范围是已有受控草稿，正式条件独立保留。
- **已有确认值不需重复处理**：本批字段有来源绑定确认，继续沿用，即使库中缺失或存在历史冲突。候选不能覆盖当前值。
- **仅资料库长期完善**：版本未知、未确认规格、历史渠道/品牌等差异及候选选择问题。完整技术问题和证据保留后台，不统一当成本批计算前置条件。

按事项用途分类，后一行可以同时拥有已确认当前值和长期资料问题，不能把各类原行数相加。正式缺项和权限也不因前台清单缩短而消失。

## 版本与参考分层

`unknown` 保持空缺；`confirmed_no_independent_version` 必须有明确证据哈希、引用和确认，不能默认生成；`known_version_conflict` 保留候选版本冲突。历史只有一个版本值也不能据此确认当前商品版本。规格冲突不伪称版本冲突。

基础参考与严格身份匹配分别统计。本候选没有任何自动采用历史值、自动确认身份或批准材质的代码路径。复用本批确认值不等于扩大跨批覆盖率；严格匹配统计直接保留P2-B原口径，不通过降低完整性标准制造提升。

## 验证入口

Python依赖沿用已有`openpyxl`；源码只引用标准库和其只读接口。真实配置及全部输出放私有本地目录。

```powershell
python -X utf8 -B analyze_private.py --config <私有配置.json>
python -X utf8 -B -m unittest discover -s tests -v
node build_business_list.mjs --model <分析目录/business-model.json> --output <新业务异常清单.xlsx> --previews <后台预览目录>
```

Excel用已配备的`@oai/artifact-tool`公共API创建，只交当前异常和分类概要。没有事项就明确显示0，不输出长期待填商品行。完整技术背景引用原P2-B计划及其哈希，保留所有原候选/被拒候选、原行和来源的可追溯关系。

私有配置包含：新`output`目录、`batch_label`、`p2b_plan`、现有`batch`/`trace`/`provenance`、确认原表`sources`和既有结果`outputs`（各含internal/customs）、冻结`engine_scripts`、`existing_pair_directory`、`protected_files`（路径→预期哈希）及`analysis_inputs`。先校验所有保护哈希，调用原引擎的只读`verify`，再与实际双表逐格比对、独立核对数量金额/税金关系，最后重新检查哈希。原表20/33列观察合同固定，不替代或扩展现有适配器。

本候选面向已确认且已生成的真实样本做可行性回放，不是完整的新批次受理器。源文件、确认或现有结果绑定失败时终止分析，不能报告为零异常；纯策略测试另覆盖当前真缺值/未确认/冲突必须进入待办的负例。

# 周边材质查询 SOP 与操作手册

版本：V2.0｜日期：2026-11-09｜依据：KMT20261101 实际查询、候选核验与交付记录

适用对象：业务操作员、查询 Agent、批处理程序维护人员。

本手册总结当前工作区实际验证过的方法。同事提供的《周边材质批量查询SOP操作手册.docx》作为参考资料；其中其他批次的耗时、命中率、站点称谓和历史事故未经本次独立复核，不当作本批实测结论。网站接口和可访问状态会变化，使用前须小样本检查。

## 一、先看这张操作卡

1. 读取用户当前接受的最新表，确认表头，备份并记录 SHA256。
2. 仅取目标材质列仍为空的商品，统计行数和不同 JAN 数，保留渠道、日文名、规格及行号。
3. 先复用身份一致且证据完整的缓存；同 JAN 共用下载结果，每行分别核验。
4. 用 JAN 查询快速站点，同时把未完成项按渠道送往对应官方商品页；JAN 无结果时再查完整日文名。
5. 找到页面后核对 JAN、角色、款式、版本、颜色、尺码和单品/BOX 范围。
6. 提取完整材质及组件、百分比、“等”，翻译并保留原文和来源。
7. 完成 100 个不同 JAN 保存检查点与独立展示版；不足 100 个的尾批也必须保存。
8. 冻结候选，重新读取磁盘，仅向仍空的目标格写入合格结果。
9. 核对新增数量、候选落表情况、非目标单元格、公式/cache 与媒体，交付表格及剩余原因清单。

查无、网络失败、无材质、身份冲突和未完成查询必须分开记录。一次流程结束只表示该轮已执行，不代表所有站点都成功取到商品页。

## 二、任务范围和输入输出

### 2.1 本批列位

| 列 | 内容 | 使用方式 |
| --- | --- | --- |
| C | JAN/商品编码 | 首选检索键，按文本保存 |
| G | 规格 | 核对款式和包装范围；采购数量尾数保留 |
| J | 日文商品名 | 次选检索键及身份核验 |
| N/O | 人工品类/材质 | 保留原值 |
| P | 渠道 | 对应厂商/官方商店的定向线索 |
| Q | YD | 来源上下文，不能独自证明材质 |
| R | 网站查找材质 | 本批唯一材质写入列 |
| S/T | 材质参考/盒规原文参考 | 保留原值 |

列位仅适用于本批；新批必须按表头重新定位，不能沿用固定列号。渠道值可能是厂商名称而非网址，先确认其真实官网或官方商店。

### 2.2 必需产出

- 独立材质补查 Excel：本批 R 填中文材质；未取得合格证据的格保持空白。
- 逐商品证据：目标行、JAN、日文名、规格、渠道、站点、详情网址、原文、译文、查询时间、身份核验和响应快照 SHA256。
- 查询状态与检查点：每个 JAN 每站的执行结果、下一待查站、停站状态及队列归属。
- 剩余清单：逐行原因、已查站点、受阻站点及尚未完成步骤。

本批不新增网址/站名列；证据独立保存。不触发业务采用、材质审批或 A03 确认，不切换日常受控指针。

## 三、查询顺序与渠道分流

### 3.1 实际推荐流程

缓存复用 → JAN 快速查询 → 渠道官方页 → 日文名精确回退 → 允许访问的其他零售来源 → 未解决项记录。

Anime Store → Colleize → AmiAmi 是已实现的快速流水线；Jump 只对相关渠道商品使用，AMNIBUS 适合 arma bianca。渠道队列应尽早并行启动，避免所有商品逐个盲跑全部网站。并行以不同站点为单位，同一域名共用限速和停站状态。

“查到即可停止”指已获得身份明确、材质完整的证据。仅找到商品、材质不完整或身份待核时，继续下一来源。不得把不同款式的材质拼成一个商品结果；若官方与零售材质不一致，优先复核组件范围与版本，不能只靠网站排名自动消除冲突。

### 3.2 本批验证过的渠道路线

| P 列渠道 | 优先路线 | 本次可用后备来源 |
| --- | --- | --- |
| movic | MOVIC 官方商品详情 | Neowing、METALBOX、Hobby Genki；仍需逐 JAN 核对 |
| Bushiroad Creative | 官方商品/活动页对应详情 | Tsurumai 等精确商品页；活动图只作导航 |
| arma bianca | AMNIBUS / arma bianca 官方商品页 | 已有精确 JAN 零售记录辅助建立身份链 |
| Caravan | COCOLLABO 官方商品页 | Neowing 精确 JAN 商品页 |
| Chugai Kogyo | 中外官方商店 | Neowing 精确 JAN 商品页 |
| A3 | eeo 等对应官方商品页 | 已验证身份的零售详情；未找到仍留空 |

渠道能缩小检索范围，不能替代商品核验。同一厂家可能生产纸品、亚克力、纺织品、金属及混合材质。

## 四、操作员逐步操作

### 步骤 A：开工盘点

1. 打开当前最新 Excel，核对目标页签和列位，检查是否有用户新增数据或正在编辑的锁文件。
2. 备份原文件，记录路径、SHA256、总商品行数、目标非空/空白行数、不同 JAN 数及重复行映射。
3. JAN 按文本处理，不截位、不补前导零、不把内部码自动修成 JAN。校验位异常单独记录，不擅自改码。
4. 生成待查记录：行号、JAN、日文名、规格、渠道、YD。规格末尾采购数量保留，不当盒规或材质依据。
5. 统计渠道分布，分配互不重复的 JAN/渠道范围和唯一队列负责人。

### 步骤 B：缓存与快速接口

1. 缓存必须能回溯到原始页面/JSON、URL、时间和哈希；仅有旧表材质文字不够。
2. 确认缓存商品与当前行的 JAN、日文名、款式/包装一致；身份变更的旧结果不复用。
3. Anime Store 用商品 JSON；无合格材质再转 Colleize、AmiAmi。
4. 队列处理 50 个不同 JAN 后，按真实完成速度评估剩余时间；不要以单次请求 0.4 秒推算整批。

### 步骤 C：按渠道和日文名查

1. 查询“JAN + 渠道/厂商名”，定位该商品官方详情。
2. JAN 无结果时，查“完整日文名 + 渠道 + 素材/材質”，只在必要时移除排版符号、统一全半角和空白。
3. 找到完整商品页，核对作品、角色、版本、款式编号、颜色、尺码和单品/BOX。
4. 页面不显示 JAN 时，可采用经过人工/Agent 明确审核的精确名称回退；记录“页面不显示 JAN”、匹配依据及排除的同名异款。若有旧零售 JAN 证据连接到官方页，保留两段身份链。
5. 搜索摘要、活动目录、缩略图只作线索；未取到可核验详情原文的候选不直接落表。

### 步骤 D：提取并复核材质

1. 阅读“素材/材質/材料/Material”等明确字段，抓取连续的全部材质内容。
2. “仕様/スペック”只有明确含成分时才可采用；“全 N 種”“W×H 尺寸”等不能当材质。
3. 保留本体、底座、贴纸、挂链、扣件等原文明示组件关系；保留百分比、“等”和限制范围。
4. 多行材质不得只取第一行；尺寸、产地、发行商等无关字段从译文中剔除，完整原始响应仍留证。
5. 原文只写“金属”就译金属；“レザー”不能无依据细化为 PU，“ブリキ”译马口铁，不能简化成锡。
6. 未知词保留原文，不按常见品类补成分。网页未说包装材质时，不自行加包装塑料/纸盒。

### 步骤 E：冻结、写回、交付

1. 下载 Agent 只提交候选和证据；由一个写回者统一合并。
2. 冻结候选列表及 SHA256，验证每条身份、材质原文、译文与响应快照。
3. 写回前重新读取磁盘文件，确认 JAN/日文名/规格/YD 仍一致，只填仍为空的 R。
4. 对既有非空 R 的更完整来源另列修订项；本轮只补空白时不得自动覆盖。历史上已授权的比例补全/官方材质修订须有单独审计，不能成为新批默认覆盖规则。
5. 保留原 Excel ZIP 成员，仅替换目标工作表中获准的 R 单元格 XML。现有带图片/公式缓存表不能用普通整表重存替代此保全步骤。
6. 从磁盘回读检查新增格、未采用候选和剩余数；核对其他格、公式/cache、图片、页签、隐藏行、筛选与保护状态。
7. 交付独立 Excel、查询证据及剩余清单，明确这轮查询受阻或未完成的范围。

## 五、接口和程序维护说明

以下地址是本工作区使用过的路径，不保证长期稳定，也不表示具有厂商承诺的开放 API 服务。

| 站点 | 已验证路径/字段 | 维护要点 |
| --- | --- | --- |
| Anime Store | `https://anime-store.jp/products/<JAN>.js`；variants.barcode、title、description | 校验实际 barcode，不因 URL 带 JAN 就认定一致；404 为当前路径无商品，不能推断全网无商品 |
| Colleize | `https://api.colleize.com/api/goods?name=<JAN>&sortType=RECOMMEND` → `/api/goods/<id>`；janCode/material | 详情再次核对 JAN；不要裸抓全站 goods 列表 |
| AmiAmi | `/api/v1.0/items?s_keywords=<JAN>&pagecnt=1&pagemax=20&lang=ja` → `/api/v1.0/item?gcode=<gcode>` | 使用现有适配器配置；jancode 精确核对，提取 spec/memo；400 是请求异常，不是商品查无 |
| Jump | `https://jumpcs.shueisha.co.jp/shop/g/g<JAN>/` | 仅相关商品查；现脚本 4530430 前缀过滤只是本批优化，不能当所有新批的完整目录规则 |
| AMNIBUS | 商品名检索后读取详情素材 | JAN 检索覆盖不全时改完整日文名；本批已验证名称+规格与旧 JAN 证据链 |
| COSPA | Product/hasVariant 中的 gtin13、SKU、颜色、尺码和 specification | 不能拿一个尺码材质代替全部变体，尤其混纺比例不同的颜色 |

### 5.1 并发与错误处理

- 本地现有参数：Anime Store 每请求至少 3 秒、Colleize 5 秒、AmiAmi 3 秒、Jump 8 秒、AMNIBUS 2 秒；新增官方/零售站通常 5 秒起步。这些是当前配置，不是不会限流的保证；Anime Store 3 秒仍曾收到 429。
- 同站单队列；搜索与详情都计请求。多个 Agent 共享同域名的配额，不能各自按同一速率叠加。
- 403/429：立即停域名相关请求、保存响应及待办；本轮不换子域、代理、浏览器工具或其他接口继续访问同一受阻资源。
- 503、超时、证书或解析失败：记技术错误，不记“无材质”。本批 MOVIC 连续 503 后停站；后备来源应是独立正常来源。
- 若站点明确给出 Retry-After，保留该值；只有已有规则允许且冷却条件满足时才恢复，不通过重启清空停站记录。
- TLS 验证保持开启；如本地 Python 信任链问题，可用系统信任链正常验证，不能关闭证书校验。

### 5.2 当前脚本入口与边界

| 文件 | 用途 |
| --- | --- |
| `tools/fast_material_batch.py` | 本批快速站点查询、缓存、断点与 R 填空检查点 |
| `tools/patch_website_material_r.py` | 在原 ZIP 成员结构内替换目标单元格 |
| `tools/merge_fast_material_evidence.py` | 合并主队列和独立候选，输出材质表与审计 |
| `reports/channel-material-agent1-20261109/` | MOVIC/Caravan/Crux 定向来源候选与审计 |
| `reports/channel-material-agent2-20261109/` | arma bianca/Chugai/A3 定向来源候选与审计 |

只读规则自检：在项目根目录运行 `python tools/fast_material_batch.py --test`，本批覆盖 20 项材质、比例、组件、身份冲突与网络失败情形。

这些脚本硬编码了本批源文件、输出目录及部分列位，属于本批工具，不是已发布的通用系统。新批先配置新路径、表头映射、独立 state 和证据目录，验证后再执行。不要把旧 `--recover-colleize-failed` 当作任意新批入口；它针对本批延后 93 个 JAN。`--limit 50` 也不能单独确保隔离运行，必须先隔离状态与输出。

当前合并器会从本批固定快照/LIVE 和候选重建输出；若用户已在最终文件修改数据，禁止直接重跑覆盖。必须先与最新文件比较，改为以最新文件为底、仅填空白。正式执行合并前保留当前交付副本。

## 六、证据结构与查询状态

### 6.1 建议统一的候选字段

| 字段 | 内容 |
| --- | --- |
| source_sha256 / run_id | 输入快照与本次运行标识 |
| rows | 当前行号及 JAN、name_ja、spec、channel、YD |
| site / url / queried_at | 来源站点、商品详情地址、时间与时区 |
| http_status / query_status | 网络响应与业务结果分开存 |
| material_original / material_zh | 完整原文及保留结构的译文 |
| identity / match_method | exact_jan / exact_name_fallback / evidence_chain 及逐行接受理由 |
| snapshot / content_sha256 | 原始响应路径、编码与原始字节摘要 |
| next_site / owner | 下一站及唯一队列负责人 |

统一用业务 `query_status=candidate` 表示待审核成功候选，HTTP 200 仅放 http_status。HTTP 200 只能证明成功取得响应，不能单独批准身份或材质。

### 6.2 原因分类

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| selected | 身份、材质、组件核验通过 | 写回前再核当前行 |
| not_found | 本站正常响应但未找到精确商品 | 下一站/日文名/渠道 |
| no_material | 已取得正确商品详情但无明确材质 | 下一独立来源 |
| identity_conflict | JAN、角色、尺码、版本或包装不符/不充分 | 排除或人工复核 |
| http_400 / network_error / parse_error | 请求、连接、编码或解析失败 | 保留异常，不能记查无 |
| blocked_403 / rate_limited_429 / stopped_503 | 访问受阻或站点暂停 | 保存剩余队列，独立后备来源 |
| not_applicable | 本站范围不适用 | 不算已检索商品 |
| delegated / pending | 已分出但未完成 | 收回失败项继续后续站点 |

一个商品可能同时有查无和访问受阻，原因应多标签记录，不能强塞为唯一“未公开”。只有真实读取正确商品详情且无材质字段，才可写“该页面未公开材质”；不能据此说全网未公开。

## 七、材质翻译与完整性示例

| 原文 | 合格中文参考 |
| --- | --- |
| 紙、スチール等 | 纸、钢等 |
| 綿100% | 棉100% |
| 本体：アクリル／台座：ABS | 本体：亚克力；底座：ABS |
| 本体：PVC・ABS／ステッカー：紙 | 本体：PVC、ABS；贴纸：纸 |
| アクリル、紙 | 亚克力、纸 |
| 本体：ポリエステル・鉄・PVC／ボールチェーン（金属） | 本体：聚酯纤维、铁、PVC；珠链（金属） |
| ブリキ、PP | 马口铁、PP |
| 未知成分、紙 | 未知成分、纸（未知词按原文保留） |

数字、百分比、组件映射和“等”逐项对照原文。整段原文必须在证据中保留；S 列既有材质参考原文不因此改写。

## 八、提速方法与时间估算

1. 同 JAN 下载一次，每个重复行单独核身份；同渠道合并搜索上下文，不合并材质判断。
2. 已有缓存先核验；不重复下载已冻结的精确页。
3. 用公开商品 JSON/API 获取结构化资料，少做页面渲染；拿到页面不等于材质完整。
4. 已知渠道尽早查询官方页，尤其 arma bianca 的 AMNIBUS 名称查找；避免只做 JAN 搜索后误以为官网无商品。
5. 不同站点并行，维护主站队列、渠道队列和剩余回收队列；代理只查询，统一写回。
6. 每 50 个 JAN 统计真实吞吐、网络请求数、命中及待人工核验量。每 100 个 JAN 保存检查点，交接所有失败和未处理项。
7. 有经过验证的旧索引才复用；本批不为一次查询新建全站合集索引，也不假定全站接口“不限流”。

时间估算应取最近样本的“完成 JAN/分钟”，考虑同站串行搜索+详情、重定向、失败和身份核验。多站并行用关键队列耗时估算，不把各站时间简单相加。40 分钟只能作为待验证目标，本批没有完整端到端计时证据，不能称已实现全批 40 分钟。

## 九、本批事故与修正规则

| 问题 | 实际影响 | 后续检查 |
| --- | --- | --- |
| 分出的 200 个 JAN 只做 Colleize，失败 93 个未接回全站链 | 早期交付仍有后续站未执行项 | 委派必须交回 success/failed/unprocessed 三份清单；失败转下一站 |

## 本地接口

已有Python/openpyxl环境，在本目录独立进程运行，无需安装：

```powershell
python -X utf8 -B -m native22 prepare --request prepare.json --output 一个不存在的新目录
python -X utf8 -B -m native22 preview --request return.json --output 另一个不存在的新目录
python -X utf8 -B -m unittest discover -s tests -v
```

准备请求沿用A-01的 `batch_id`、`input_file`、可选 `library_config`。只新增后台宿主的 `price_basis`：

```json
{
  "batch_id": "本批业务标识",
  "input_file": "原件.xlsx",
  "price_basis": {
    "schema": "a-price-basis/1",
    "source_sha256": "本次原件SHA256",
    "currency": "JPY",
    "purchase_column": "G",
    "comparison_column": "N",
    "purchase_role": "purchase_price_reference",
    "comparison_role": "source_business_unit_price",
    "evidence_ref": "确有的本批价格口径确认出处"

```

依据须由可信宿主按真实对话/业务资料建立，不能伪造；它明确本批价格字段口径，不是采购价格真实性、商品身份或申报资料的专业批准。仅本地接口，宿主身份尚未在WorkBuddy验证。没有依据时不自动补齐：准备副本仍可用，但报告一个批次级前置问题，明确未执行验算，不逐格制造全批红格。错误币种、原件摘要、列映射、零售/最终金额角色或 `approved=true` 等额外参数拒绝。

回传请求与A-02相同：`context_file`、`uploaded_file`、可选 `box_corrections`。宿主上下文为 `a02-trusted-context/1`，包含 `current_output`、`business_batch_id`、`export_id`、`a_version`、完整 `known_outputs`。新入口能读旧登记；旧格式不启用新价格口径时直接调用原A-01/A-02，维持原行为。

## 格式与编辑范围

22列先由实际表头匹配：A箱号、B原产地、C编码、I日文名、J单个价、K倍数、L单个数、M Qty、N日方业务单价、O金额、Q材质、R渠道、S YD、T备注。固定完整命名锚点成立后，才使用已确认的空表头槽：D辅助码、E中文名、F规格、G采购价格参考、H盒规、P品类、U验算、V取整价。允许这些空槽填写已知对应表头，但不猜其他布局，不自动接受任意重排列。16列版价格比较列仍为K，原第3步及raw格式不套22列位置。

普通回传允许E/F/P/Q/R/S，以及非公式G/H的提案；C改码、原为空的B补值分别待核。YD可空；材质仅参考。原M数量、L单个数、N价格、O金额、J/K计算、D/V辅助公式、T备注、箱号及箱重页等受保护。新生成的H/U公式也受保护，不接受人工直接覆盖；盒规公式格更正仍从对话形成独立提案。

复用A-01的只读资料查询，白名单来源/排除本批及最终答案的规则不变；只补空格。已有非空价格不覆盖，不从日方价格或历史最终金额倒填采购价。候选价格/盒规即使填入，仍独立待采用，不记为价格核验正常。

## 取整与价格规则

移植用户批准的核验示例，仅用于A阶段参考验算，没有重写B计算核心。

- 价格以ROUND_HALF_UP取两位参与计算，源价格原值保留，G及比较价格格显示两位。金额/数量不改。
- 原H是已知G÷比较单价公式时，副本将其变成受控四舍五入整数公式；原H为正整数数值时保持。原公式及原缓存留在来源记录，原件不动。
- U用两位价格×当前H计算两位价差，绝对值严格大于100 JPY标红；±100不超限。不得用未取整的G/N原样带回，形成恒等0。
- 缺价、非数值价格、负价、比较价格取两位后非正数、盒规取整为0或非正整数，均不出正常价差，不补1、不猜价格或补0。未知H/U公式保留并归组，不执行任意公式。
- 正常取整和有效数值盒规分别归入程序处理组，不逐格制造人工待办。异常按原因归组，保留每个原行；组数不是实际真人操作次数，也不代表可以整组批准。
- 价格口径缺失是批次级前置问题。价格/盒规候选、人工改价格/改盒规、改码/规格变化另列待核，不能因数值看似正常就自动采用。

## 保全与回传

只在新登记副本更新允许的H/U计算公式及其受控缓存、价格显示精度和警示填充；其余公式/缓存、原值、行序、箱重、附页和样式定义保持。用A-01局部OOXML工具及批准示例的受控补丁方式，逐格还原校验、旧样式追加校验、非目标部件原字节校验，再重开核验。未知下游H/U依赖拒绝发布，避免留下旧计算缓存。登记包含源公式证据、工作公式、来源及价格依据、字段状态、行对应、快照摘要和A版本。

回传复用原A-02全部逐格比较和B2排他归档，不复制其审核页逻辑。比较通过后，**从已发副本的登记观测值＋本次明确修改提案重新核验**，不信任上传文件自行变动的公式缓存。价格/盒规/身份关联变化仍是待确认提案，不修改当前A版本。预览没有业务Excel交付或业务提交事件；用新 `read_preview` 核对外层摘要、基础预览和价格快照后显示。

原表未嵌入版本ID的边界延续A-02：宿主须保留完整已发出登记；已知旧版/其他批次/多版本歧义拒绝。不伪称能认证未登记且只读内容完全相同的旧文件。所有输出必须使用新目录；晚失败工作簿或预览隔离。

`confirmed=false`、`can_enter_b=false`、`formal_output=false`始终保留。初始副本登记可以复用Store建立全新只读来源快照，不是A-03人工确认保存；回传绝不调用Store.save或B2 commit。真实人工操作数、节省工时和全批业务异常总数未测，保持null。

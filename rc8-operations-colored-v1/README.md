# rc.8 运营计算与两表标色独立后继

当前运行时为 **0.8.0-rc.5**。这是无业务数据的源码同步，不是安装包、部署记录或正式放行。仓库根目录保留之前的 rc.3 源码；使用本候选时须显式选择本目录的入口和独立持久输出路径，不能与根目录模块混合加载。

## 当前实现

- 独立映射支持第3＋4步运营表、19列 H/I/J 布局及20列 I/J/K 已确认成品布局；按表头识别，保留原行序、内部F款式、备注、YD原值。
- 保存源文件哈希、工作表、行号、原单元格、公式和缓存；单位、特殊换算、重复编码配对及分摊范围以来源绑定确认。
- 正常拆分价格使用精确 ROUND0；内部确认金额保持原值，海关金额按执行单价×申报数量计算。仅保留已提供且核验一致的本批执行价，不自行找行调平。
- 组合税率采用本批确认分摊结果，或依明确权重重新分摊；不猜权重，不默认跨批税率/VAT。
- 输入、受控草稿和正式关务三层门禁分开。正式字段不足不统一阻断可计算草稿；必要数值缺失不补造。
- 只交海关表和内部到货表。浅黄=取整/分摊/参考，橙色=人工调整，红色=真正缺项/待确认；技术证据留后台，不新增复杂审核页。

正式输出始终关闭。本次不接数据库、网站，不自动外发；保留的旧资料库模块/合成夹具仅供兼容回归，**不会批准归类**，不表示运营路径已接入数据库。已有版本、安装与业务原件不覆盖。

## 本地运行与测试

Python 3.11+，依赖见 Skill 的 requirements.txt。下列命令从本目录执行：

```powershell
python -m pip install -r workbuddy/japan-arrival-customs/requirements.txt
python -X utf8 -B -m unittest discover -s tests -v
python -X utf8 -B workbuddy/japan-arrival-customs/scripts/run.py --output <独立持久输出目录> workbuddy --request <请求文件.json>
```

运营入口和确认流程见 [Skill](workbuddy/japan-arrival-customs/SKILL.md) 与 [计算和交付口径](workbuddy/japan-arrival-customs/references/operations-delivery-policy-v1.md)。这些程序参数应由 WorkBuddy 构造，不让运营手写。

本地完整回归曾通过110项（含显式提供的私有原始样本）；不提供私有输入时，一项实样测试应跳过。最新修改版双表的私有回归通过，逐行金额/顺序/原内容、箱重、公式缓存、标色及保存后核验均有本地证据。真实工作簿、金额、商品、逐行差异、哈希、路径、日志、截图和结果表不入库。脱敏周报见 [本周进展](../docs/WEEKLY_PROGRESS_20261030.md)。

WorkBuddy 原生触发、可信身份、双表显示/保存仍为**未验证**；不能把 CLI 测试当作实机验收。

# 统一明细合同 0.1

范围：首票 KMT 第3步表、JPY、本地单人离线审核。不是对所有历史供应商模板的通用识别。业务仍需确认本批金额来源版本、计价单位与审核角色；本合同的技术状态流不是对 D01–D08 未决业务细则的批准。

| 结构 | 内容及来源 | 确认要求 |
|---|---|---|
| schema / id / revision | `japan-arrival/1`；输入路径、SHA及阶段确定批次；文件SHA＋sheet＋源行生成技术行号 | 技术ID不充当商品编码/JAN/YD |
| sources / source.cells | 原件路径、SHA、阶段、表、行、各字段单元格/缓存值/公式/类型 | 原件只读；旧文件哈希失配即拒绝继续写审核 |
| raw | P0解析的源值字符串；错误值原样保留 | 不覆盖旧版本、零值不当缺失 |
| identity | 原始商品码、日文名、版本、规格、关系预留 | 编码非13位原样保留，无编码仍保留行；改码/拆分不自动建立关系 |
| product | 内部名、独立申报名、品类、渠道、YD、前台状态及无值原因 | 正常匹配批量确认，争议单独说明；确无前台/YD合法 |
| authority | 第3步金额、币种、计价数量/单位、观察单价及源行 | 数量金额与原始证据绑定，审核API不能修改；价格确认单独记录 |
| material | 未审历史候选、已选原文/完整译文、来源、适用context | 已审同版本/规格历史优先预填；仍需本批明确采用，不能自动批准 |
| packaging | 采购/申报/内部单位、申报倍数、内部数量/盒数、每盒件数、来源及context | 仅显式人工核准系数；未知为null，不从“全8种”或价格比推断 |
| tax | 已批税率、增值税率、税基单价/单位、归类、日期、来源、公式版本及context | 不设默认税率；仅`historical-box-v1`明确批准参数可演算 |
| logistics | 当前源箱号、产地 | 物流完整对账及源1/3/5跨表附件适配留P1-B，不能据此声称397箱重量已完成P1核验 |
| reviews | product / identity / price / material / packaging / tax各自确认人、时间、依据 | 商品批量确认不替代专业审核；身份变更使材质/盒规/税率确认失效 |
| disputes / events | 每个争议ID、所属域、原因；每次变更前哈希、操作者、依据及值 | 纯价格/材质/盒规/税率争议不阻断完整商品资料批量确认，且不因商品确认消失；商品/身份及未知域争议仍阻断。已确认商品不得直接重复确认，纠错先补录使确认失效；历史版本不覆盖 |

所有十进制数以字符串传输，拒绝浮点、NaN和Infinity。计算使用Decimal校验和Fraction精确分数，`5/3`代表精确比例而非可写入正式海关单价。未批准精度/尾差不取整。金额核验同时保存行差、商品/版本/规格/币种/单位分组差和批次差；任意行不一致都不能靠其他行抵消。无编码记录不被当作同商品合并。

现有盒装税金：显式批准参数`price, duty_rate, vat_rate`，`duty=price*duty_rate`，`vat=price*(1+duty_rate)*vat_rate`，`box_tax=(duty+vat)*(internal_quantity/internal_boxes)`。每盒件数须与该比例一致。无默认13%、无税率猜测、无汇率/运费/采购成本计算、无金额量化。改变盒规或归类/申报品名后，税率确认作废待重审。

海关字段预览仅构造申报名、产地、已确认材质和精确价格比例；不复制原工作簿、源文件名、内部名、渠道、YD、备注或元数据，并拒绝申报名包含已知内部名/YD/渠道。此为内部预览接口，正式白名单及模板尚未批准，不能用于外发。

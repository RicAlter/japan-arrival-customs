# P3-B 独立新业务批次验收

基线`f420951`。本目录只有验证用运行器和验收说明，不修改P3-A、rc.5、P1/P2-B/P2-C、资料库或正式门禁，不新增生产模块。

## 新批次资格

必须有可追溯的真实原始附件、明确批次和本次确认范围，且未参与开发/验收。文件改名、复制、旧批次分表和衍生审核文件不能作为独立新批。开发前期已经扫描或用于规则分析的历史批次，也不能因没出现在近期回归文件名中就认作“从未参与开发”。资料库跨批参考命中本身不等于使用过该批次，但须独立核对样本来源和先前使用记录。

没有合格新批次时，真实识别/映射、计算、查询、异常数量及双表结果全部标记未验证，异常数量用null，不复制旧结果交付，也不用合成样本替代。不能在没有真人操作时宣称测得节省工时。

## 分开记录的证据

| 范围 | 需要证明的内容 |
|---|---|
| 独立真实批次 | 来源资格；真实输入识别/映射；单位和例外确认；原计算；资料库只读查询；P2-C分类；双表核验与业务复核 |
| 合成安全用例 | 字段完整、当前缺值/冲突、无候选、库不可用、版本不兼容、篡改及半份交付拒绝 |
| 旧批次回放 | 只作已知回归基线，不计算为独立真实批次验收 |
| 真人操作 | 哪些字段实际输入/确认、候选怎样呈现、双表怎样领取；无观察就记未验证 |

原P3-A入口接受“已确认运营表”，不是通用日方原始附件自动补全入口。必须如实记录谁提供/确认了名称、材质、数量金额、单位和特殊换算；程序确认消息不能代替真人或可信宿主确认。候选不覆盖当前确认值，长期版本/规格问题不混入当前必填。

## 合成用例复跑

用独立Python进程运行既有P3-A测试；临时合成数据库和表格只存在于测试环境。

```powershell
python -X utf8 -B p3b-validation/verify_synthetic.py --output <全新私有验证目录>
```

运行器逐项记录`sample_kind=synthetic`，即使测试名称包含`real_calculation`，也只表示调用真实计算代码，不是用了新的真实业务样本。运行器成功只证明这些自动检查通过，不代表P3-B真实新批验收通过。

真实候选清单、附件路径/哈希、逐行结果、人工记录及本地报告不得提交GitHub。此次没有合格新批次时，不安装WorkBuddy；进入业务试运行的结论保持暂缓，不能把P3-A技术通过替代P3-B独立实样证据。

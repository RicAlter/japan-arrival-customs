# B-00 计算业务依据及分组确认

独立候选；使用A-03/B2的不可变对象、版本、CAS、互斥锁及重复回执。仅写 `Service.fork` 显式建立的隔离保存副本，冻结A-01～A-03验收目录不可直接写。本模块不生成Excel或双表，也不批准材质、税率、归类或D1规则。

## 读取与确认

- `Service.preview_basis(batch_id, business_file=..., groups=[...])`：只读取已验证的第3步业务列，复用rc.5表头匹配、精确乘法、单位白名单；逐行保存来源文件SHA、工作表和原格坐标。原行号＋箱号＋编码＋日文名＋来源规格共同匹配，不按JAN猜改码或拆分关联。候选规格不参与身份升级。
- 组字段：`row_ids`、`business_unit`、`declaration_unit`、`reference`、`exceptions`；可选`declaration_factor`（默认1）。后台展开明确行ID，不支持通配批准。相同依据可一次确认一组；不符合规则的行留在excluded，未选行不保存。独立单个数量必须符合业务数量×本组系数。
- `commit_basis(plan_id, confirmed_hash=plan_id, explicit_confirmation=True, reference=明确出处)`：只确认已展示范围，重读来源，检查SHA和A版本，再保存到A新版本。回执、H采用、数量金额版本和换算关系随HEAD一起提交；重复同计划返回旧回执。保存前中断保留旧版，保存后中断从当前回执恢复。
- `read_basis(batch_id)`：独立返回到货观察、当前业务数量/单位/金额、保存历史、采购数量空缺、日方零售金额未提供状态。到货Qty不补采购数量，G采购参考不补业务金额。来源变化拒绝读取；A变化使旧业务依据失效。
- `preflight(batch_id)`：重新调用A-04，获得当前计算前检查。后续消费仍需A-04 `current_input` 复读当前版本，不能直接拿旧JSON运行。

22列原表不能仅因Subtotal来自日本单价就被当作已确认业务金额。本模块要求独立第3步业务依据。业务I/J/K仅在明确确认当前文件/行范围后成为本批算术依据；不读取海关最终G/P形成金额或规则。采购价候选、材质参考和专业审批保持独立。

## 两层盒规及Qty

H始终保存物理每盒件数：独立单个数量÷独立盒数。rc.5旧模型的 `packaging.pieces_per_box` 在混合Qty表中可能是“每盒计价数量”，因此另外记录 `legacy_internal_quantity_per_box`；通过单个数量、业务数量、盒数及本组明确系数验证两者关系，不改原计算核心。

A-04仅增加对已保存B-00范围证据的兼容：普通物理单位沿用旧逻辑；`Qty（原表计价口径）/单个`仅在B-00存在当前A版本、文件SHA匹配、明确换算关系时采用。没有B-00范围的旧接口行为不变。任一A修改使该范围整体过期，不能续用旧计算输入。

## 本地隔离验证

历史KMT20261003：只复用已有确认记录的出处与单位范围、第3步I/J/K与H盒数，以及22列原表L单个数量。默认系数1，1794行可确认，173行特殊换算继续待核；没有从最终成品金额或数量反推。历史批量保存属于隔离回放，不作为新批真人签核。

非1系数的分组能力使用合成证据测试；并未对历史173行自动批准。当前未补齐资料的22列和16列A-03原保存状态继续保持0行可计算。

CLI：`python -X utf8 -B -m basis fork|preview|confirm|read|preflight --root 隔离目录 --request 后台请求.json`。业务通过对话表达确认范围，后台准备参数；无需新确认Excel。

身份追溯采用宿主上下文；本地无真人身份时记录unverified，不冒称关务或专业审批。正式门禁保持关闭，WorkBuddy原生环境未验证。

# 重建路线与开发方案

路线：独立重建、按项复用旧能力。日常按R0资料库→R1接表匹配→R2运营回传→R3计算箱重→R4最后填图双表推进；按已具备字段局部处理，不要求整批无缺项才继续。

| 阶段 | 工作单元 | 完成标准 |
|---|---|---|
| R0 | 来源盘点、结构设计、商品入库、采购入库、清洗关联、查询抽样 | 来源用途、版本、币种单位及出处明确；原始、候选、人工采用分开；禁止来源不能经缓存绕过 |
| R1 | 识别来表、匹配补资料、处理新增/修改/重复 | 表头变化可配置，主码/PCS/名称及采购路径完整，不合并同码出荷行，不覆盖人工内容 |
| R2 | 确认表、差异回传、局部续做 | 固定认可布局，校验版本和原始字段，合格范围保存，异常单列，人工结果可承接 |
| R3 | 数量包装、价税金额、箱重 | 个/包/盒语义和价格单位明确；可算部分继续；箱重去重；差额不静默调平 |
| R4 | 图片两阶段、双模板输出 | 先记录链接和缺图，最后嵌图；原图保全；内部到货表与海关草稿可核对 |

资料库采用独立SQLite候选和来源证据分层。当前MVP最小库不代替全量资料库；暂不要求先完成全部历史迁库才开发后续业务功能。

九个基座沿用F01来源、F02身份、F03采购、F04商品资料、F05箱货、F06计算、F07回传、F08图片、F09双表。阶段实现、程序验证、运营认可、专业判断与正式安装分别记录。

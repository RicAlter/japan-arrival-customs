# 仓库卫生与数据隔离

## Git 中允许保留的内容

- Skill 说明、Python 源码、依赖清单与不含业务资料的参考文档。
- 不可反推真实业务的合成测试和测试代码。
- 说明性配置样例；其中不得出现有效账号、令牌、哈希、路径或业务身份。

## 严禁提交的内容

- 到货、物流、报关、内部到货或历史工作簿，以及从它们生成的任何 Excel/PDF/压缩包。
- 决策库对象、SQLite 索引、审核事件、运行目录、预览、截图、报表和哈希清单。
- 真实商品名、JAN、YD、渠道、价格、税率、人员、审批凭据、会话、令牌、环境变量或绝对本机路径。

`.gitignore` 默认忽略旧资料目录、运行状态与常见缓存。它不是访问控制：本机业务资料仍应存于受权限保护的位置。

## 本地运行布局

推荐在仓库外创建业务运行根目录，例如：

```text
<受保护目录>/incoming/       # 人工放入的原件，只读
<受保护目录>/batches/        # Skill 批次状态与审核回传
<受保护目录>/knowledge/      # D1 独立决策库
<受保护目录>/exports/        # 草稿和获批后的受控输出
<受保护目录>/security/       # 可信会话配置；不进入仓库
```

仓库代码升级时，保留这些目录并以显式 `--output`、`--library` 等参数引用。不得将它们移回仓库以求方便。

## 上传前检查

```powershell
git status --short
git status --ignored --short
git diff --cached --check
git diff --cached --name-only
```

逐项检查暂存文件，确认没有业务资料、运行文件或凭据后再创建提交和推送。发现疑似资料时，先取消暂存而不是修改或删除原件。

- 主源码：`codex/0.7.0-isolated-development`，`41e498eb903847e58cbcdf5d86039539996edac3`（rc.4）。检查时仅有未跟踪的 PLAN.md。
- 商品资料库候选：原工作区 `codex/local-product-library`，尚无提交。rc.5代码、商品资料库和单人模式为未跟踪成果，采用逐文件移植，不声称已合并某个不存在的提交。
- 集成分支：`codex/report-template-integration-rc6`。原分支、冻结0.6.0、WorkBuddy安装目录及业务运行目录不变。

## 使用方法

安装候选ZIP后，使用一个主Skill：上传日方原始Excel，发送“处理这批日本到货”。初步整理与三页审核表继续生成。随后发送“生成海关和内部到货表”。

已有回传表时，发送“这是我修改后的审核表，继续处理”。差异预览成功后，可以要求“使用这份候选预览生成海关和内部到货表”。WorkBuddy在同一个workbuddy请求中传入当前批次和preview_id。程序重新核验B2导出登记、上传哈希和批次版本，仅展示候选，不执行return-commit。

```json
{"message":"生成海关和内部到货表","batch":"<程序返回的批次ID>","preview_id":"<当前已登记预览ID>"}
```

无preview_id时仅使用当前已保存批次及其本地商品资料库候选。不同候选预览使用不同输出目录。同版本重复执行会重读校验已有文件，拒绝覆盖或交付损坏文件。

统一CLI仍是 `scripts/run.py --output <独立运行目录> workbuddy --request <请求文件>`。原 `render-drafts` 增加可选 `--preview-id`，没有新增独立业务生成入口。

## 字段与计算

- 原表路径的海关草稿采用历史第5步的33列、表头、列宽、行高、冻结和格式。申报品名仅取customs_name，内部商品名、YD、渠道、内部备注不得进入可见或隐藏内容。
- 内部草稿采用历史第6步20列及8列箱重页。Qty保留仓库原始点数，日文描述、内部名、YD和本批内部备注按允许范围保留。
- 商品按本批稳定源行生成。历史成品2688行与本批2687行不作行号拼接。编码以文本保存，避免前导零和长编码丢失；内部D列使用文本拼接公式，替代可能损失前导零的历史TEXT数字格式化。
- 箱号沿用原表分块向下填充及既有区间展开核对。Q/R/S仅在匹配到的箱重组首次出现时填写一次；箱号显示保留原写法，不猜分摊单箱重量。
- 已签核换算才生成申报数量。有限精度单价必须精确复现该商品已确认金额；非终止小数、未确认金额或未知单位留空待审，不调平，不抵消商品差额。
- 未确认输入下，金额、盒数比例、税金和内部合计公式返回空白。历史0.13、R列两种税金算法、体积/10000均未作为新批准规则采用。税基单位与模板单价一致且已有有效税费和包装审核时，才复用原box_tax结果及已批准增值税率；其余保持待审。
- 新版只安装从已验收预览提取的表头和样式JSON，无历史业务行。每次新建两份工作簿，追加处理说明和明确草稿标识；不复制历史工作簿中的批注、名称、隐藏页或嵌入对象。
- 为兼容冻结回放，旧第三步批次原技术草稿接口保留。新版式用于原表业务主路径；旧12/21列技术草稿不再被描述为最终业务模板。
